# 原生注入点有功功率上限

本入口只复用 PVsyst 8.1.6 的 `pvSystem` 数值限值与原生仿真，不在适配器截断功率、重算损失或执行储能削峰调度。温度、PF、kVA、P50/P90 和文件限值不由本切片配置。

## 入口与范围

先复制方案，再用 `pvsyst_get_variant_parameters` 取得当前事务令牌。通过现有 `pvsyst_update_variant_parameters` 提供：

```json
{
  "project": "WORKING.PRJ",
  "variant": "VCB",
  "expected_sha256": "<current-token>",
  "grid_limit_updates": {"mode": "constant", "limit_kw": 250},
  "dry_run": true
}
```

检查预览后，使用同一未变化源的当前令牌执行 `dry_run=false`。限值为正、有限数，按原生保存的 0.1 kW 精度提供；示例250是验证输入，不是工程建议。`mode=none` 不带 `limit_kw`，关闭限制并移除限值/单列损失标量，但保留原生未启用的位置标志。

这是独立参数事务，可附带已有显示名称修改，不能混入角度、容量、积灰、模式或储能修改。复用既有无操作、备份、恢复与并发保护；不改源项目、组件、天气、主阵列损失或硬件数量。

受限范围为版本8.1.6、PV-only Grid、一个无活动阴影/布局的普通固定平面和子阵。系统必须为已核验的扁平结构，PF/负荷/储能、其它系统标志、未知字段或非所属限值字段在写入前报具体原因，而不是被删除或忽略。检查结果中的 `grid_limit` 只报告可识别的系统状态，不证明任意场景、拓扑或设计适用性。

## 原生绑定与对照

原生 `TSystemeAddForm` 并网页选择 Active power、注入点、单列损失，保存到 owning `pvSystem`：

```text
Flags=$05000000
SystemType=Grid
PLimGrid=250.0
LimGrSeparLoss=True
```

原生另存的逆变器端控制为Flags=$01000000；关闭注入点限制后Flags=$04000000，且两个标量消失。这证明启用位和位置位不同。系统bit27是允许/禁止注入，既不是数值限值也不是网充；本切片遇到该模式会阻断，不重解释其语义。

CLI 8.1.6 的固定式440kWp/360kWac示例、同一2022年SIT/MET、完整8760小时参考：

| 原生GUI配置 | 年并网电量 kWh | 最大小时 E_Grid kW |
|---|---:|---:|
| 关闭限制 | 799980.9366 | 352.11 |
| 注入点有功250kW、单列损失 | 693356.8866 | 250.00 |
| 逆变器端250kW、单列损失 | 693356.8866 | 250.00 |

原生PDF第3页明确Active power、注入点、250kWac；第5页显示Unused energy (grid limitation)和693357kWh。两种位置在这个无下游AC损耗的夹具中相同，不据此宣称一般位置差别已验证。

`pvsyst_build_sfi(variables="grid_limit")` 在共用变量之外加入原生 `PGridLim`、`EGrdLim`、`EUnused`、`EOutInv`。`PGridLim` 是限值，不是实际传输电量；本例`EGrdLim`为正、`EUnused`为零。启用单列损失时`EOutInv`不是受限的最终并网列，应查看`E_Grid`；关闭模式可能省略限值列。保留原生列，不做后处理补齐或能量修正。

## 实现验收

真实新stdio MCP会话已完成：公开schema、复制新方案、预览不写入、正式写入、无操作不备份、关闭、恢复和11项写入前阻断。启用与关闭后的派生文件分别与原生GUI参考VC6/VCA逐字节相同；恢复回启用时文件也精确还原。比较的是实际格式/内容，不执行哈希测试，生产事务令牌与保护保持原样。

MCP原生全年输出8760行、17个数值列，与GUI配置的原生全年参考逐点一致，包含时间戳、表头和单位；最大E_Grid=250kW。关闭后的原生24小时与原生关闭年度参考前24行一致，限值列按软件行为省略。共用范围校验的积灰回归再跑24小时、15个数值列，与已验收的GUI常数2.5%年度参考前24行一致。

11个负例覆盖布尔/字符串数值、零、负数、超出0.1kW精度、常数模式缺值、关闭模式带值、未知模式、未知字段、与角度合并及真实GUI PF方案；每次阻断后输入内容保持原样。这个集合不声称验证所有未支持模式，只确认被公布的范围边界和典型误用。

本机记录 `grid-limit-public-acceptance-r9.json` 保留实际公开调用、参数、返回及结果摘要；原生参考输入和CSV仍在隔离case中，不上传仓库。编译与diff检查通过。没有运行全量发现、旧smoke或哈希测试；没有新增计算模型、依赖或永久测试框架。

此前同组GUI批量另存已取得温度/PF字段候选，但未纳入此验收：温度模式的原生消费、PF/kVA互动、下游AC损耗的位置差别、P50/P90、文件限制和储能削峰仍待分别验证。GUI临时脚本发生过模态就绪断言和内存标题误写，均在隔离副本内记录、恢复；后续关闭时GUI已退出，原因未证，原工作区键已经读回恢复。它们不被包装成本MCP垂直切片的通过项。
