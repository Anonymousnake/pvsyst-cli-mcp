# 原生辅助功率与AC损耗验证

辅助功率入口只保存原生字段，功率、运行时段、损耗和并网能量由PVsyst计算。本阶段使用GUI/CLI 8.1.6.49278、无阴影固定单平面440kWp/360kWac副本及原有2022年气象文件；原文件保留。

后续扩展：`mode=profile` 已增加两个受限原生阈值/比例族，原constant/none接口不变。新范围、GUI整文件与8760h原生对照见[详细损失批次](native-detailed-losses.md)；以下保留原常数阶段的历史边界与证据，不把后续两族扩成任意混合辅助模式。

## 已接入接口

`pvsyst_update_variant_parameters` 新增独立 `auxiliary_updates`，允许同时改显示名，其他参数另开事务：

```json
{"mode":"constant","operating_kw":5,"night_kw":2}
```

`operating_kw` 是整个系统在原生逆变器运行条件下的常数功率，不是按时钟定义的白天曲线；本入口限定原生输出阈值为零。`night_kw` 是原生待机/夜间辅助功率。两值均须明确给出，非负、0.01kW步长；0/0保留使能，`{"mode":"none"}` 关闭并移除字段。检查接口返回 `auxiliaries` 当前模式和两项kW值。

原constant/none阶段范围限定为8.1.6、PV-only、单子阵/固定平面、无活动阴影或布局、已验证主阵列标志的并网方案。当时比例/非零阈值尚未开放；现在仅新profile两族另行验收。PF、负荷/储能、限值组合及未知字段继续在写入前停止；不隐式清理或覆盖未知配置。既有预览、无操作、备份与恢复事务复用，生产并发保护保留。

| 原生绑定 | GUI实验值 | 保存结果 |
|---|---:|---|
| owning `pvSystem.Flags` bit18 | 启用/关闭 | `$00040000` / `$00` |
| `AuxPower_Const` | 5.00 kW | `5000.000` W |
| `AuxPower_Night` | 2.00 kW | `2000.000` W |
| `AuxPower_Pout`，未开放 | 10.0 W/kW | `10.000`，独立GUI消费已证 |

GUI启用0/0时只存使能位，不存零值字段；关闭移除辅助功率字段。单位转换来自实际GUI往返，不是厂家或工程假设。

## 原生消费与MCP验收

独立GUI控制覆盖未改、零值使能、运行5kW、比例10W/kW、夜间2kW、关闭、运行5/夜间2组合。2022-01-01的24小时运行中，零值使能和关闭与未改控制的所有14列、时间戳、单位完全相同；三项非零输入均改变原生输出。夜间2kW的最小 `E_Grid=-2kW`。导出有数值精度，逐列差值只是观测，不替代原生辅助损耗计算。

运行5/夜间2组合另做全年：8760行、14数值列，`E_Grid=768273.9359kWh`，最小值-5kW；部分低输出时段也可能由电网补给辅助消耗，不把负值抹零。7页原生PDF第3页列出5.00/2.00kW，第5页列出原生辅助损失-3.96%及768274kWh并网能量。

真实stdio MCP再创建 `AUXILIARY_POWER` 工作工程并执行完整验收：

- 公开schema、预览不写入、零值使能、运行5/夜间2、关闭、恢复和无操作不备份全部通过；零值、启用、关闭文件分别与GUI参考逐字节相同。
- 13个误用/范围负例均保持输入原样，含布尔/字符串、负值、保存精度、换算溢出、缺值、未知模式/字段、混合事务和未支持原生状态。
- MCP全年CSV的8760行、14数值列、单位和时间戳与独立GUI组合的原生全年参考完全一致，并重新生成原生PDF。
- 共用范围校验的注入点限值250kW再跑24小时，17数值列与此前GUI年度参考前24行完全一致。

没有新增专用辅助损耗SFI枚举：结果名定位代理未交付，不猜变量名。现有原生 `E_Grid`/`EOutInv` 和PDF用于本次对照，不把两列差值对外包装成通用辅助损耗公式。

## AC线路与限值位置

GUI另建每逆变器100m、10mm²铜线控制，原生保存涉及主阵列使能位、每个拥有的逆变器分支 `CableDefinition`、`Length=100 m`、`Material=Copper`、`StdCrossSect=ISO60228_10` 以及子阵缓存。不是只改一个ACWireLength标量，因此尚未开放AC编辑器。

进入线损页时，原生还把既有DC电阻36.9117423071806mΩ重写为36.912mΩ。本次AC对照使用同页关闭控制，避免混入该格式差异；关闭控制的14列仍与原基线相同。

该非零AC场景的2022-01-01实测：无上限时并网最大332.30kW；注入点250kW时并网最大250.00kW；逆变器端250kW时并网最大246.93kW，注入点方案当天多并网15.340kWh。这补上此前无下游AC损耗时两种位置输出相同的歧义。结论限于此24小时场景，不等于所有地点或全年均已验证，也未扩大现有限值编辑器到AC活动标志。

## 记录与剩余范围

本机 `ac-aux-native-r11` 保留GUI原始/控制变体、截图、`native-consumption-r11.json`、`auxiliary-public-acceptance-r12.json`、全部原生CSV/PDF及恢复记录，不上传商业模型和气象文件。GUI正常退出，唯一DataPath键恢复并读回。临时GUI/验证脚本完成后清理。

初次GUI启动超过临时5秒就绪阈值，断言停止在输入前；确认窗口就绪后继续。首个MCP临时验收脚本误用旧SDK属性inputSchema，在任何复制/修改前失败，改用当前input_schema后完整通过。这些是临时调用偏差，不计为产品通过项。比例/阈值、辅助与PF/限值/储能耦合、AC变压器及其他教程缺口继续保留；没有全量发现、旧smoke、哈希测试或外部损耗模型。
