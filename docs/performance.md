## 第一轮起点

本轮先测现有实现，再做两项局部改进：显式工具组选取、标准SFI时间戳快路径。保留Python，未引入新运行时依赖、持久结果缓存、外部物理模型或通用性能框架。默认82工具的名称、Schema与描述保持。

## 测量条件

2026-10-26/27，本机Windows11 build26200、CPython3.12.10、当前MCP SDK2.x。使用真实stdio ClientSession与新Python服务进程，非可执行CLI夹具防止调用PVsyst。已有跟踪结果CSV为542248字节、8784小时、13实际数值列；只复制和读取既有输出，不重算全年。

每个配置启动3个进程，每进程测4次list_tools、6次只读简报、3次年度CSV摘要；解析器另测7次。启动包含新服务进程、导入和MCP initialize，不包含模型推理或原生仿真。系统文件缓存未清空，不称作操作系统冷盘启动；运行顺序和宿主负载影响计时。catalog按工具内容的紧凑UTF-8 JSON计算，不是完整RPC包，也不是模型Token数。

## 显式选组

在客户端原有env对象中增加：

```json
{
  "PVSYST_TOOL_GROUPS": "setup,engineering,results"
}
```

这只是新增环境项示例，不替换PVSYST_CLI或PVSYST_WORKSPACE。省略变量保持全部82工具；8个可用键为setup、projects、components、weather、storage、simulation、results、engineering。大小写敏感，允许项间空白；空项、重复、未知键均在启动时报错。

app只导入所选的固定工具组，注册器也核对活动工具名。未公开工具不进入MCP目录，也不接受其MCP调用；已选严格入口继续检查未知顶层参数，严格注册完整性只核对当前活动集合。此项是每进程的发现／调用配置，不是多用户隔离或新的原生许可控制，工作区和软件原有约束继续生效。修改后重启服务。所有组仍共享同一CLI与进程内工作区锁；没有为获得吞吐率而并行操作同一桌面或工作区。

## CSV热点

原解析器在每一行调用通用strptime。一次cProfile观测中，8784次strptime及其子调用累计约0.286秒，占该次约0.593秒解析过程的48%；剖析本身有开销，不把此值当普通调用时长。实现只为固定ASCII `DD/MM/YY HH:MM` 使用标准库fromisoformat的C路径，1969..2068两位年份窗口保持；非标准但历史可接受的格式继续调用原strptime。日历、闰年和范围仍由标准库验证，不自行实现日期算法。

随后在同一个进程交替执行旧版与新版，先排除2轮预热，再取11轮中位数：

| 同一8784行CSV完整解析 | 中位耗时ms |
|---|---:|
| 原版 | 314.8460 |
| 改进版 | 148.7539 |

该配对观测减少52.75%，约2.12倍解析吞吐；逐行原生值完全相同。它不是PVsyst发电／储能仿真加速，也不是所有规模或机器的保证。

公开年度摘要在独立轮次中的中位耗时从167.68ms到99.78ms；工程选组下100.82ms。此项不是配对测量且有明显宿主噪声，仅记录观测，不把约40%的差值当严格因果或回归阈值。默认前后完整摘要JSON一致。

种子20261026的临时差分共10012个输入：包括5000个格式化时间点及逐一随机字符变体，加世纪窗口、闰年、非补零、额外空白、Unicode年份和无效格式。新版与原strptime的日期值／ValueError类别无差异。原严格读取继续报无效时间，宽松读取继续跳过；缺测不补零，分页total不因只取小页而少算。没有放松完整年、单位、有限数值、生产指纹或输入漂移检查。
