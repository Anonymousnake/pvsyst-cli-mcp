## 状态与新入口

新增的 `string_mismatch_updates` 是独立事务，可附带 `variant_name`；`subarrays[].string_mismatch` 返回该子阵的原生模式。支持 `{"mode":"constant","loss_percent":2.5}` 或 `{"mode":"default"}`。常数0.01..100%、0.01百分点增量是适配器域，不声称软件完整范围；默认模式不臆补数字，getter 的 `loss_percent` 为 null。只改 owning `pvSubArray.Flags` bit17 和 `PMismString`，不改模块失配 `PMismMPP`、其它标志、组件电参数或缓存。输入行按原生 `PMismUFixe` 后的位置保存。

`auxiliary_updates` 增加 `mode="profile"`，原 `constant`/`none` 输入形状和作用保持。新模式必须显式给出五个量：

```json
{
  "auxiliary_updates": {
    "mode": "profile",
    "operating_kw": 0,
    "night_kw": 0,
    "operating_threshold_kw": 0,
    "proportional_w_per_kw": 10,
    "proportional_threshold_kw": 5
  }
}
```

仅开放两族：常数运行功率>0、运行阈值>0、其余三项为0；或比例项>0、比例阈值≥0、常数/运行阈值/夜间为0。混合、带夜间新模式、全零 profile 保持待验并在写入前停止；全零新项使用原 `constant` 模式。新模式两功率0.01kW、阈值与比例0.1原生单位增量。Native Const/Night 用W，序列化复用既有1000单位换算；CThresh/PThresh 对应本轮GUI输入kW并原样保存数值，Pout对应W/kW，不计算辅助负荷。

新入口限8.1.6、PV-only、单普通固定平面/子阵、自由地平线、完整电路计数及已验主阵列/子阵标志。与其它物理编辑、P50、温度、PF、限值、活动AC、老化、负荷/储能耦合不在本次域中。未知/重复/非 owning 字段不被清理。新 profile 源若属于未验混合族也停止；原 constant/none 不因新增 profile 而被扩成混合编辑器。

## 依赖与边界

DC两种输入同时改 `pvSubArray` 的RSCablage字段、默认位及 `pvCircuit` 多个CableDefinition阻值；MV还把InverterNode包入TransformerNode。GUI参考Pac(STC)431.5kW与铭牌360kWac不同；自定义百分比和存储损失分数也不直接相等。不用外部公式反算电阻、等效电路或变压器损失。

IAM三态在变体 `pvSubArray.PVObject_IAM` 中独立保存，含模型字段与原生TCubicProfile/LastCompile等曲线数据；不自行重算菲涅尔/ASHRAE。老化含 `DegradLossFactor` 等派生保存量，KeepMCValues=False和RMS0仅证明本样本未保留样本数组，不证明内核没有随机路径。PAN组件IAM、详细研究/电缆工具、交互损失图、MC保留/恢复、更多电路与气象前置仍继续待验。

本机证据：`loss-window-map-r26.json`、`loss-save-batch-r26-r2.json`、`transformer-save-batch-r26.json`、`hv-save-r26.json`、`loss-native-r26.json`、`uv-wind-native-r26.json`。两次驱动断言失败保留：默认框不能按普通开关强行取消；HV使用参数表而非灰色百分比输入。修正后续跑不覆盖原样本，GUI正常退出、原UTF-16 DataPath读回恢复。
