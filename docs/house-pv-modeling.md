# 房屋与光伏：PVCollada 2.0

`pvsyst_create_house_pv_scene(project, variant, output_name, house, layout, dry_run=True, module_geometry=None)`

主路径是 **AI 一次生成基本完整房屋的构件网格，工具薄序列化为 `.pvc2`**。AI 决定墙体、多片屋面、挑檐、门窗外形、烟囱、门廊和同栋房屋的附属体量，不再被程序的平顶/双坡模板限定。工具不执行 AI 提交的代码、不增加几何引擎或替代遮挡模型，只复用标准网格输出、组件和光伏引用，并校验输入。旧矩形平顶/双坡调用保留兼容。

所有遮挡、辐照和发电量由 PVsyst 原生计算。本工具不编辑原生 VC，也不自动操作 GUI 导入。文件写入成功、原生导入成功、原生仿真成功是三个独立状态；返回 `imported=false`、`native_consumption_verified=false`，不把参考方案验收外推到每次新输入。

## AI 一次提交房屋

`house` 使用 `{"kind":"mesh","meshes":[...]}`。每个构件必须完整给出三个字段：

| 字段 | 内容 |
|---|---|
| `name` | 可读构件名称，1..120 字符，无首尾空格，忽略大小写后唯一；例如 `PV roof`、`West wall`、`Chimney` |
| `vertices` | 局部米制坐标数组，每项严格为 `[x,y,z]` 三个数值 |
| `triangles` | 显式三角索引数组，每项 `[i,j,k]`，零基整数、在界且三个索引互异；多边形由 AI 先三角化 |

AI 应根据用户尺寸/草图生成整栋房屋的全部必要构件，一次提交，而不是连续调用“加一面墙”。没有尺寸依据时须先取得输入或明确标注建模假设，不将推断尺寸表述为现场测量结果。门窗可表达为贴面、凹进或洞口几何；字段名称不赋予玻璃透光或建筑物理语义。是否闭合、自相交、法向和原生遮挡效果仍需原生检查。

每栋上限 128 个构件、累计 50000 顶点和 100000 三角。这是接口负载上限，不是 PVsyst 官方或建筑工程限制。坐标沿用六位小数；在实际序列化后的坐标上检查退化三角，防止舍入后边长归零；派生几何运算溢出也在写入前停止。响应返回构件数、名称和几何摘要，不重复回传整个顶点输入。有限坐标、非退化三角和格式通过不代表房屋拓扑或工程设计已经认证。

### 光伏显式放置

AI 网格模式的单区域 `layout` 恰为以下七个字段，取代旧模式的退距/净距自动起点；单区域的行列乘积匹配整个源方案。多区域采用下述 `tables` 形式：

| 字段 | 内容 |
|---|---|
| `module_rows`, `module_columns` | 严格正整数，乘积匹配源方案实际组件总数 |
| `orientation` | `portrait` 或 `landscape` |
| `row_spacing_m`, `column_spacing_m` | 非负米制模块间距 |
| `origin_m` | 光伏板块低侧局部起点 `[x,y,z]`，由 AI 在整栋场景中一次放好 |
| `roof_mesh` | 支撑屋面构件的精确名称；须是独立、共面、法向向上的表面网格，而非含上下底面的屋顶实体盒 |

倾角和方位继续继承源普通固定朝向。支撑屋面法向须与光伏平面一致；检查四角的竖直投影分别落入该屋面的三角并集，且各角不低于屋面。该检查不证明网格连通、没有洞口或整块光伏绝不跨越凹口/其它构件，也不代替实体相交或结构校验。整栋房屋其它屋面形状不受平顶/双坡枚举限制。

房屋构件使用普通 COLLADA 网格和节点，不发明 `pv:house` 或 `pv:window` 标签。内部生成唯一引用 ID，构件名称写入标准 `name`；光伏的模块/rack/table/实例引用、米/毫米单位与站点元数据仍由已验证的薄序列化代码组装，AI 不必每次重复整套 XML 样板。

### 同朝向多区域

`layout={"tables":[{"name":..., ...单区域七字段}, ...]}`，每区有独立行列、间距、起点和支撑面名称。只在 `tables` 内要求名字忽略大小写后唯一，不与房屋构件名争用命名空间。支持1..64区（接口负载界，非原生限制）；**所有区域的行列乘积之和**匹配源方案总组件数，单区可以是20+20，也可以15+25，而不是每区重复整个阵列。

每区独立写标准rack/table/instance引用，内部ID统一分配；所有区使用同一源PAN和普通固定朝向，倾角/方位不由AI另设。共面且内部相交的光伏矩形会得到 `pv_tables_overlap`，相邻接边不算重叠；这只是明确的排布输入检查，不替代PVsyst的对象穿透、遮挡或辐照模型。单区域和旧参数调用保持兼容。

### 修正反馈

保留原 `issues` 字符串列表，并增加 `diagnostics`，每项有 `code`、`path`、`message`、`repair_hint`；适用时包含构件 `part` 和零基三角序号 `triangle`。例如 `house.meshes[3].triangles[7]` 精确定位坏面，不再只返回“几何错误”。可同时返回多个构件的问题，最多披露100项，截断时 `diagnostics_truncated=true`。发现重复共点三角、六位小数后退化、坏索引等时停止写入，不擅自修补AI网格。

AI应按这些位置修正原输入，再预览，成功后创建**新文件名**。这是复用同一create入口的修正循环，不是通用CAD内核。家具、室内陈设、精细五金、材质渲染和暂停功能均不增加。

### 原生几何检查

PVsyst8.1.6三维编辑器的 **工具→检查场景有效性**（本机中文菜单Alt+Y、X）已实测。正确场景返回“此场景正确。”；只移动烟囱使其穿过第一块光伏后，软件返回“物体 '物体17' 和物体 '表格21' 相互干涉”。检查未被禁用，没有另写碰撞计算器。原生对话框Ctrl+C可复制正文；仅读取本次原生复制后的文本，不读取先前剪贴板内容。

这证明一个受控对象/光伏穿透案例，不外推为所有自相交、屋面孔洞、结构或建筑物理检查。导入/绑定仍走原生入口，自动MCP封装另行验证。

新文件在标准 `asset/contributor/authoring_tool` 标识方言版本，在 `asset/subject` 存小型来源/原布局/屋面关联JSON，供读回修订；不重复整栋网格，不自创 `pv:project` 标签，也不暗示已原生关联。来源声明仍须在重新创建时由实际工程核对。

## 旧参数接口

| house 字段 | 单位 | 含义 |
|---|---|---|
| `length_m`, `width_m` | m | 矩形房屋的局部 X / Y 长宽 |
| `eave_height_m` | m | 檐口高度；平顶时即屋面高度 |
| `roof.kind` | — | `flat` 或 `gable` |
| `roof.pitch_deg` | ° | 仅双坡，严格大于 0 且小于 90；须与源光伏倾角一致 |

双坡屋脊平行局部 X，位于宽度中线，光伏放在前坡。返回 `roof_rise_m` 是屋脊相对檐口的升高量，绝对屋脊标高为 `eave_height_m + roof_rise_m`。

| layout 字段 | 单位 | 含义 |
|---|---|---|
| `module_rows`, `module_columns` | 个 | 严格正整数，乘积须等于源方案的 `NModSerie × NStringCh` |
| `orientation` | — | `portrait` 或 `landscape` |
| `row_spacing_m`, `column_spacing_m` | m | 模块边缘间距，非负 |
| `clearance_m` | m | 板块低边相对屋面的竖直净距，非负 |
| `edge_margin_m` | m | 局部 X 的退距；局部 Y 在平顶按水平退距、双坡按坡面退距解释 |

所有字段显式传入，不自动摆满、不推断工程间距。倾角和方位来自源方案的唯一固定朝向，布局不接受另一个倾角/方位覆盖值。

| module_geometry 字段 | 单位 | 含义 |
|---|---|---|
| `model_name` | — | 组件实际型号，不从文件名猜测 |
| `nom_power_wp` | Wp | 名义功率 |
| `width_m`, `length_m` | m | 组件宽度、长度 |
| `geometry_depth_m` | m | 显式几何厚度，不推断厂家规范 |

可读 PAN 优先从工作区、再从已配置内置松散文件库读取。根 `LargApp`/`LongApp` 与商业信息块 `Width`/`Height` 都按已有米制声明解析，重复/冲突停止；型号、功率和尺寸须与调用方提供的元数据一致，写前复查源字节。

原生初始数据库引用不一定有独立 PAN 文件。此时必须显式提供 `module_geometry`，返回 `metadata_source=caller-provided-for-native-database-reference`；这不是数据库或厂家已校验声明。源有可读 PAN 时也要显式提供几何厚度，因此当前完整 `module_geometry` 对实际创建仍是必需输入；参数默认空只会返回具体缺项。

## 示例

下列数值是本机验证夹具，不是住宅设计推荐。原方案含 1000 块组件，所以对应大屋面；住宅项目应绑定其自身的组件数量和硬件，不照搬本例。

```json
{
  "project": "ROOFTOP_IMPORT.PRJ",
  "variant": "VCD",
  "output_name": "Roof_Gable.pvc2",
  "house": {
    "length_m": 120,
    "width_m": 60,
    "eave_height_m": 8,
    "roof": {"kind": "gable", "pitch_deg": 15}
  },
  "layout": {
    "module_rows": 20,
    "module_columns": 50,
    "orientation": "landscape",
    "row_spacing_m": 0,
    "column_spacing_m": 0,
    "clearance_m": 0.3,
    "edge_margin_m": 2
  },
  "module_geometry": {
    "model_name": "Mono 440 Wp 72 cells bifacial",
    "nom_power_wp": 440,
    "width_m": 1.052,
    "length_m": 2.131,
    "geometry_depth_m": 0.035
  },
  "dry_run": true
}
```

确认预览后使用 `dry_run=false`，只新建 `UserData/<output_name>.pvc2`，源 PRJ/VC/PAN 不写。默认预览不创建文件或目录；禁止覆盖、大小写同名、越界路径、未知键、布尔/字符串充当数字及非法 XML 字符。失败披露产物路径，保留原生检查提示。

## 原生导入流程

PVsyst 8.1.6 实测路径：近处遮挡 → 建模/透视图 → 文件 → 导入 → `Import a 3D scene (3DS, DAE, PVC, PVC2, PVZ2)`。核对米制尺寸、模块数量以及完整导入摘要；此版本始终提示 PVC2 支持为 beta。

本机导入会创建新的朝向，即使屏幕上倾角/方位与原有朝向相同。仅显示模型尚不满足系统关联：

1. 在三维编辑器按 `Shift+Ctrl+O` 打开原生朝向管理工具。
2. 将新朝向的三维场区拖到原系统朝向；原生提示参数差异时，本机参考选择“修改光伏场区的参数”，不启用平均朝向。
3. 删除已空的新朝向，不删除光伏场或系统子阵；核对原朝向同时包含系统和三维场区。
4. 关闭场景，核对组件数量、面积和朝向兼容性，使用原生表格/重算，再另存新方案并重载。
5. 对新方案使用既有 `pvsyst_run_simulation(..., recompute_shading=true)`，保留实际 CSV 列、单位、PDF 和所有警告。

这组原生绑定步骤尚未被宣称为一个自动导入 MCP 工具。`pvsyst_create_house_pv_scene` 不调用未证实的 CLI 导入参数、不直接写场景私有位，也不放宽旧固定式无阴影编辑器的门控。

## 格式与范围

- COLLADA 1.5，几何米制、`Z_UP`；PV 扩展命名空间 `https://pvcollada.org/2026/XMLSchema`、profile `PVCollada-2.0`。`pv:module` 的长宽厚为毫米，只有该处做单位转换。
- 房屋构件是无 PV 标签的普通 mesh；AI 路径逐构件保存，不强制每个墙面或屋面独自闭合。旧参数路径仍生成封闭体：平顶 8 顶点/12 三角，双坡 10 顶点/16 三角，原生分别保存为6面/7面。PVsyst会合并共面三角，不保证保持输入三角分面形式。
- 房屋与光伏共用父节点 Z 旋转，光伏平移在房屋局部系中。源 PVsyst 方位转为地理北 0 顺时针：`(180 + FieldAzim) % 360`，本批限定北半球。
- 四角几何包容检查、模块计数、有限数值和屋面净距检查不是遮挡或电气模型。当前六位小数坐标表达不接受会被写成零的微小非零值。
- 源侧仅一个普通固定平面、一个 Grid 子阵、完整电路计数、内嵌站点；活动场景/布局、负荷/储能/P50/已存地平线停止，不悄悄保留不一致映射。
- Module Layout/电气阴影、其它朝向和跟踪类型、DC 耦合与电网充电、特殊原生负荷、随机电网停运依用户要求暂缓；不作为本建模阶段的能力声明。

## 多区域与诊断验证（R45）

AI一次提交20构件、110顶点、80三角的实验住宅，主体20×12m，前屋面增加天窗，两个光伏区域之间留出2.152m空带；这些均为明确假设，不是现场尺寸。原生40块、17.6kWp/两台Generic9kW硬件沿用R44源，新增工程只复制其实际PRJ/VC文本，不猜电气限值或气候设计条件。

新公开MCP契约含23个错误输入/多构件错误/重复面反例、两个根级网格数量反例、同名并发一建一阻、旧单区AI及旧参数预览兼容；均保留失败或停止的真实返回，坏输入未写新文件。两区20+20与15+25分别通过官方XSD和三组Schematron。协议仍65个工具，没有为每面墙或每块光伏新增工具。

PVsyst8.1.6导入两种布局均明确为2个光伏对象+20个Other对象，仅beta提示。原生保存与重载分别是5×4+5×4及5×3+5×5，源模块总数40、总敏感面积89.67m²，2个table均关联NoOrient=1，组件/PAN/逆变器/站点/气象保持。原生表计算、场景有效性正例和单变量烟囱穿透反例均实测；反例未保存进正常变体，取消时明确选择不保留修改。

| 2022原生全年方案 | 年并网电量 kWh | 原生输出 |
|---|---:|---|
| 无场景同硬件基线 | 32791.8296 | 8760连续小时、13数值列、7页PDF |
| 20+20分区住宅 | 32784.2599 | 8760连续小时、14数值列、8页PDF |
| 15+25分区住宅 | 32784.1766 | 8760连续小时、14数值列、8页PDF |

全部使用既有run入口并显式重算阴影表，原生数值有限、报告为Linear shadings : Fast (table)、输入字节不变；基线省略GlobShd，不补列或零。这些差值属于整场景，不声称某单个构件的因果损失。GUI正常退出，完整INI逐字节恢复，旧工程与干净源方案保留。

本阶段没有运行全量测试、旧smoke或哈希类测试，也没有加入生产依赖或替代软件的遮挡/碰撞内核。读回和自动GUI封装属于后续独立验收状态，不由这组多区域证据冒充完成。

## AI 完整住宅验证（R44）

指定模型子代理一次生成整栋实验住宅的 JSON：19 个命名构件、102 顶点、70 三角，包括前后墙、山墙、两侧屋面、四道挑檐、门窗外形、非对称门廊及柱、烟囱、同栋附属体量和门。尺寸为明确标注的实验假设（主体18×12m、檐高3.5m、前屋面15°），不是现场测绘结果；门窗是贴面几何，不声称已有真实洞口或玻璃材料。

工具只接收全部显式网格并序列化，未调用旧 `house_mesh()` 重建房型。默认预览以及实际创建通过；37 个格式/范围/几何错误均在写入前停止，同名并发请求一建一阻。旧平顶/双坡预览仍通过。另用公开克隆和朝向入口创建0°源，验证水平光伏 `drop=0` 的旧误挡已修正；该产物和完整住宅分别通过官方XSD及structure/references/business三组Schematron，未跑全量、旧smoke或哈希类测试。

PVsyst8.1.6导入摘要明确 **1个光伏对象+19个Other对象**，仅有PVC2 beta提示，无站点、海拔或组件尺寸不匹配。保存VC中为19个 `pvShdGenObject` + 1个 `pvShdArrayTable`，全部 `Source=osPVCollada`，一个组内含20项；不是20个组。构件 `name` 保留在PVC2标准属性中，但此版本原生界面仍显示“物体n”，不承诺导入名称保真。

原生系统源为40块Generic440Wp组件（10串联×4并联）、两台原生Generic9kW逆变器；该硬件仅为实验夹具。原1000块方案的公共缩放因整数分配约束正确停止，生产门控未放宽；改由原生系统入口建立独立源。GUI显示过“逆变器功率略大”提示，已保留；不是工程选型批准。场景导入后通过原生朝向管理完成40/40块、89.67m²、15°/0°关联，计算原生线性表并另存新方案，重载保持20对象和关联。站点、气象、组件和电路与源一致。
