# 原生季节朝向与地平线验证

本记录确认朝向/地平线组的持久化、原生导出/重导入与计算消费，并补充MCP只读季节字段。后续已按这些参考接入[受限季节写入器](seasonal-orientation.md)和[原生地平线写入器](horizon-profile.md)，各有新增公开配置入口与独立原生消费验收。

软件为GUI/CLI 8.1.6.49278；独立 `PLANE_HORIZON` 工程使用原有440kWp/360kWac组件、电气配置和2022年SIT/MET。试验角度和轮廓只是对照输入，不是场址设计或真实地形数据。原始文件保留。

## 季节朝向的原生绑定

`TOrientationForm` 在同一个 `TOrientGroup` 的 owning `pvOrient` 中保存：

| 配置 | 原生字段 |
|---|---|
| 固定15°控制 | `FieldType=FixedPlane`、`FieldTilt=15.0`，无夏/冬/月字段 |
| 夏10°、冬30°、方位0° | `FieldType=SeasonalTilt`、`FieldTilt=0.0`、`SummerTilt=10.0`、`WinterTilt=30.0` |
| GUI冬季勾选1/2/3/10/11/12月 | `WinterMonths=$0E07` |
| 仅额外勾选4月 | `WinterMonths=$0E0F`，仅增加0x0008 |

角度单位由实际GUI度符号和控件绑定确认。原生选择的季节类型、两个倾角及月勾选在另存后重新载入保持。普通朝向窗口未改控制与输入参数相同，季节性切换不是复制两个固定平面。

`pvsyst_get_variant_parameters` 现在额外返回原始 `SummerTilt`、`WinterTilt`、`WinterMonths`、`UsesTiltAver` 字符串；字段不存在时不发明零值。特别是季节模式的 `FieldTilt=0.0` 不代表全年水平安装。固定、两种冬月配置及季节+地平线四个真实MCP检查均通过，输入内容保持原样。普通 `orientation_updates` 的固定平面门控未放宽。

## 地平线的原生绑定

`THorizonForm` 默认显示四点方位-120/-40/40/120°、高度0°。通过GUI将四个高度都设为20°，保存并重载得到 `pvVCalcul` 层内嵌 `PVObject_Horizon=pvHorizon`；不是近阴影 `pvShading` 段，也不是 `.HOR` 路径引用。

- 手工定义后另存：Horizon段 `Flags=$01`、`FracAlbedo=1.000`，没有三个派生散射/反照率因子。
- 由软件保存 `Shadings/HORIZON_LEVEL20.HOR`，以及再从“PVsyst内部文件”导入后另存：段为 `$03`，并有原生 `FHHDiffus=0.914`、`FHPDiffus=0.864`、`FHPAlbedo=0.000`。这些数值由软件产生，适配器没有计算。
- 三者均有 `HorizonLine=TCubicProfile`、`NPtsMax=100`、`NPtsEff=4`、`LastCompile=$81`、`Mode=1`；前四点为输入，另有100行结构中的零值占位。不开推断这些标志在所有场景的含义或插值/闭合规则。
- 确认“清除所有地平线的点”再另存后，内嵌Horizon段整体移除；独立HOR文件仍保留。
- 实际导入列表同时含只读演示轮廓。已明确选择实验文件、核对四个20°点后才保存，未修改演示轮廓。

## 原生消费与交互

通过真实stdio MCP调用现有run入口执行原生CLI，不做辐照、跟踪、遮挡或发电替代计算。四组均为2022年完整8760小时、14数值列（共用13列加TArray），样本有限、时间连续；导出各自原生PDF且无运行警告。

| 方案 | 朝向 | 远地平线 | 年并网能量 kWh | PDF页数 |
|---|---|---|---:|---:|
| VCA | 固定15° | 无 | 799980.9366 | 7 |
| VC8 | 夏10°/冬30°，冬月$0E07 | 无 | 825616.5205 | 7 |
| VCB | 固定15° | 四点20° | 759037.4994 | 8 |
| VCF | 夏10°/冬30°，冬月$0E07 | 四点20° | 776665.8310 | 8 |

原生PDF第3页分别显示Free Horizon或Average Height 20.0°；季节方案列出Seasonal tilt adjustment、10°/30°和Oct.-Nov.-Dec.-Jan.-Feb.-Mar.。有地平线时报告新增页面，损失图页码也会变化，不硬编码全部为7页或第5页。

其余9次24小时控制验证：原朝向控制/地平线清除均与对应无地平线年度前24小时逐点一致；原生HOR保存和重导入两条路径，以及带/不带三个派生系数的20°轮廓，均与手工轮廓年度前24小时的14列、单位和时间戳完全一致。这只证明该日格式等效，不外推为任意轮廓/角度/全年系数等效。

额外把4月归冬的方案，在1月/7月与原季节方案完全一致，4月发生变化。1月和额外归冬的4月，分别与独立固定30°的同日14列完全一致，证明月份选择被原生计算消费，而非仅保存月mask。

## 记录、恢复与剩余项

本机 `plane-horizon-native` 保留原始/GUI控制、HOR、截图、`native-consumption.json`、`public-inspection-acceptance.json`、分组字段报告及恢复记录。共13次原生运行（4全年+9单日），不上传商业模型、天气或演示文件，不重复之前已充分验收的控制。

临时调用偏差已记录：类型组合框无Edit子窗；类型切换会重建旧句柄；文件列表包含演示条目；仅设置列表索引而不触发VCL选择回调曾暂时预览演示轮廓，但在保存变体前取消并确认回到空轮廓。之后真实点击目标列表项、检查点集才保存。文件选择窗按钮超出屏幕时只移动本次原生模态窗口。失败记录保留，不计为产品通过项。

GUI正常退出，唯一DataPath键恢复并读回。明确白名单编译、真实MCP只读检查、上述原生对照及文档/diff检查通过；没有全量发现、旧smoke、哈希测试或独立几何引擎。季节/地平线写入已另以完整文件和原生全年参考验收；Dome/跟踪、3D构建和布局映射仍是独立未验收范围。
