# 原生地平线轮廓

`pvsyst_update_variant_parameters` 的独立 `horizon_updates` 事务配置原生远方地平线，`pvsyst_get_variant_parameters` 的 `horizon` 返回点集及保存的原生标志/派生字段。这里不构造近阴影、3D场景或跟踪器，也不实现遮挡、插值或散射计算。

```json
{
  "project": "HORIZON_PROFILE.PRJ",
  "variant": "VCM",
  "expected_sha256": "<当前检查返回值>",
  "horizon_updates": {
    "mode": "profile",
    "profile_name": "HORIZON_LEVEL20",
    "points": [[-120, 20], [-40, 20], [40, 20], [120, 20]]
  }
}
```

明确给出4至100个 `[方位角, 高度]` 点，均为PVsyst内部角度，0.1°步长；方位角须在-180..180内严格递增且不重复，高度在0..90内。南0°、西正东负，来源数据有不同方位参考时须先用软件原生导入确认，MCP不猜North角或自行旋转数据。不会自行补端点、闭合或插值。全零轮廓请使用 `{"mode":"none"}`，该模式只接受mode并移除整段远方地平线；不会删除独立HOR文件。

profile_name为1..80 UTF-8字节的可打印无首尾空格名称，写拥有的Horizon Comment而非根变体名。可同时给既有variant_name；非ASCII名称要求明确BOM，行为同季节/变体命名事务，不隐式改变全文件解码。

## 原生保存与门控

复用GUI的 `PVObject_Horizon=pvHorizon` / `HorizonLine=TCubicProfile` 标签，NPtsMax=100、实际NPtsEff、LastCompile=$81、Mode=1、100个Point槽。只开放GUI参考中的FracAlbedo=1.000模板，现有其它反照率配置先停止，不假定或拟合工程反照率。

新建或变更点集保存为原生Flags=$01且不继承旧FHHDiffus/FHPDiffus/FHPAlbedo，交PVsyst使用原生流程；既有Flags=$03需三因子完整，检查接口仅披露保存值，不用其实现外部计算。仅修改名称时只换Comment、完整保留缓存；相同请求不写也不备份。响应before/after使用相同语义键，不把native_fields差异当成点集变化。

限定8.1.6 PV-only Grid、完整电路分配、单子阵/普通固定平面且全部组串在方向1、已验证主阵列标志、无活动近阴影几何/布局、无负荷/储能、普通系统Flags=$00。平均/季节/跟踪/多平面及系统耦合状态先停止；未知块、字段、标志、曲线模式、派生因子缺失和非1 FracAlbedo不覆盖。所有修改复用预览、并发令牌、备份与恢复；其它参数另开事务。
